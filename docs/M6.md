## 0. READ FIRST — what M6 is, and the guard-rail it must respect

- **M6 = a geomatics-ONLY model.** Predictors are spatial / remotely-sensed landscape layers
  *only* — no recent-case counts (that is M1), no reanalysis climate lags (that is M2). M6 is
  the spatial-layer analogue of M2's "weather only."
- **M6 is EXPLORATORY / a SENSITIVITY comparator — NOT a headline model.** The project's
  pre-registered design (`docs/geomatics_scope_of_work.md` §D) states environmental layers are
  *not* new predictors added to boost accuracy. M6 deliberately probes that boundary to answer a
  bounded scientific question, exactly as the DLNM comparator was added to answer a reviewer.
  **It must be reported as such.** Do not let M6 become "the best model" in any figure/caption
  without PI sign-off and a framing sentence.
- **The scientific question M6 answers:** *Does a purely spatial/landscape model carry any
  standalone early-warning signal — and specifically, does it beat season (M0) or climate-only
  (M2) on the registered decision metric (net benefit)?* The expected, honest answer is **no or
  marginal** — and that null is a legitimate, publishable result under this paper's thesis.
- **Non-negotiable comparability rule:** M6 is scored on the **identical test rows** as
  M1/M2/M5 for each country, using the **same evaluation code, split, threshold, and bootstrap
  seed**. If M6 cannot score the same rows, **STOP** (see §11 stop rules).
- **Data hygiene is absolute** (§2). Raw rasters, feature CSVs and predictions are **quarantined
  and git-ignored**. Only scripts + this `.md` + `M6.html` + a safe markdown report are ever
  committed. Never commit surveillance data, rasters, or feature tables.

## 6. Data acquisition — per-variable recipes

**General pattern for every raster layer via GEE:** load the ImageCollection/Image → filter to
the country bbox and (for dynamic layers) to the epi-week date range → reduce over each polygon
with `reduceRegions(reducer=mean, scale=native, crs=analysis CRS)` → export a table (CSV) to
`features/`. Always request **`mean` AND `stdDev`** (carry within-unit dispersion — WP2
discipline). For **population-weighted** means (recommended for #5,7,9,10,11,12), multiply the
layer by the WorldPop image and divide by the zonal sum of WorldPop.

> **Vintage matching (QC gate):** match every layer's year to the analysis window. Sri Lanka
> test window 2018–2025; Colombia test window 2020–2022. Never weight 2018 exposure with 2020
> population. Log the exact product ID and date range per layer.

### Batch A — DEM bundle (#1–4): one download, four features

- **Source:** Copernicus GLO-30 (`COPERNICUS/DEM/GLO30` in GEE) or SRTM (`USGS/SRTMGL1_003`).
- **#1 Elevation:** zonal `mean` + `stdDev` of the DEM per unit.
- **#2 Slope:** `ee.Terrain.slope(dem)` → zonal `mean`.
- **#3 TWI:** compute locally with `pysheds`/`richdem` on the clipped DEM
  (`TWI = ln( flow_accumulation / tan(slope) )`), then zonal `mean`. Guard `tan(slope)=0` with a
  small epsilon; fill pits before flow accumulation.
- **#4 HAND:** `pysheds` — condition DEM (fill/breach) → flow direction → drainage network at a
  fixed accumulation threshold (document the threshold) → HAND = elevation − nearest-drainage
  elevation; zonal `mean`.
- **Collinearity note:** #1–4 are mutually correlated (TWI, HAND are slope/flow derivatives).
  This is fine for a *predictive* M6 (we do not interpret coefficients), but L2 regularization
  (§9) is mandatory and a VIF diagnostic is logged.

### Batch B — open rasters (#5,6,7,8,11,12)

- **#5 Built-up:** GHSL `JRC/GHSL/P2023A/GHS_BUILT_S` (match epoch to window) or ESA WorldCover
  built class fraction (`ESA/WorldCover/v200`). Feature = built-up fraction per unit.
- **#6 Population density:** WorldPop (`WorldPop/GP/100m/pop`, year-matched) → zonal `sum` /
  unit area = density; also keep raw `sum` for population-weighting other layers.
- **#7 Nighttime lights:** VIIRS DNB `NOAA/VIIRS/DNB/MONTHLY_V1/VCMSLCFG` (monthly → **dynamic**;
  aggregate to epi-week by month-join, §7) or Black Marble. Feature = mean radiance per unit(×month).
- **#8 Fragmentation:** clip ESA WorldCover per unit → `pylandstats` → edge density + largest
  patch index + Shannon diversity. Static, one value per unit.
- **#11 Surface water:** JRC `JRC/GSW1_4/GlobalSurfaceWater` — `occurrence` (% of time water) and
  `seasonality`. Features = mean occurrence + distance-to-permanent-water (compute from the
  `seasonality`≥threshold mask). Static.
- **#12 Forest cover:** ESA WorldCover tree class fraction, or Hansen `UMD/hansen/global_forest_change`
  treecover2000 − loss to the target year. Feature = forest fraction per unit. Slow → treat annual.

### Batch C — dynamic RS time series (#9,10) — the temporally sensitive layers

- **#9 LST/UHI:** MODIS `MODIS/061/MOD11A2` (8-day, 1 km). Scale factor ×0.02, K→°C. Export a
  **unit × 8-day-composite** table over the full window. UHI variant = unit LST − rural-ring LST
  (optional). QA: drop composites with >X% cloud/gap (log the fraction; MODIS QA band).
- **#10 NDVI/EVI:** MODIS `MODIS/061/MOD13Q1` (16-day, 250 m). Scale ×0.0001. Export unit ×
  16-day table. **Temporal-leakage guard:** never use an annual composite that injects future
  months into earlier weeks — composites are dated and used only up to the feature's week.
- Both are aggregated to epi-week and lagged 0–8 weeks in §7 (mirror the climate lag design so
  M6 dynamic features are directly comparable to M2's).

### Batch D — harder / judgement layers (#13,14,15,16)

- **#13 Human mobility (MODELLED — no restricted data):**
  1. Get unit centroids (projected CRS) and WorldPop `sum` per unit (from #6).
  2. Build a gravity model: `flow_ij ∝ (pop_i * pop_j) / d_ij^β`, β=2 default (log a
     sensitivity at β=1). `d_ij` = great-circle or OSM road travel-time between centroids
     (`osmnx` drive network + `networkx` shortest path; fallback = Euclidean in projected CRS).
  3. Collapse to per-unit scalars: **in-flow potential** `= Σ_j flow_ij` and **degree/Betweenness
     centrality** of the thresholded flow graph. These two are the M6 mobility features. Static.
  4. *(Optional, free)* Meta Social Connectedness Index (HDX) as a validation cross-check — not required.
- **#14 Socioeconomic/wealth:** Meta **Relative Wealth Index** (HDX, admin-2 or 2.4 km grid) →
  zonal `mean` per unit. Static. Colombia coverage good; Sri Lanka — if RWI absent, fall back to
  a nightlights+built-up SES proxy and **document the substitution**.
- **#15 Healthcare access:** OSM/HDX `healthsites.io` facility points → travel-time surface
  (`osmnx` or a friction-surface + `skimage.graph.MCP`) → mean travel time per unit; or simple
  distance-to-nearest-facility if friction data is unavailable. Static. **Flag in the report that
  this is a surveillance/detection confounder, not a transmission driver.**
- **#16 Rice paddy / cropland:** ESA WorldCover cropland fraction (static share) + MODIS EVI
  phenology amplitude (`MOD13Q1` seasonal max−min) as a paddy-intensity proxy. Cropland fraction
  is static; phenology amplitude is annual. Keep both.

**Direct-download fallbacks (only if GEE unavailable):** DEM → Copernicus/OpenTopography; VIIRS →
NASA Black Marble (earthdata login); MODIS → LP DAAC AppEEARS (area+date request, returns CSV);
WorldPop/WorldCover/GHSL/JRC → their portals; RWI/health → HDX. All go to `raw/`, logged.

## 9. Fit M6 (mirror the ladder's model class exactly)

Write **`scripts/fit_m6_geomatics_v1.py`**. Match `colombia_model_ladder_h4_75pct_v1.py` and the
Sri Lanka ladder conventions **exactly** so results are comparable and the eval code is shared.

- **9.1 Model class:** regularized **logistic regression** (`sklearn LogisticRegression`), **L2**
  penalty, solver `lbfgs` (or `saga` if high-dimensional). No RF/XGB/NN (excluded from the
  primary replication, per ladder spec §7).
- **9.2 Features:** all M6 geomatics predictors (static + dynamic-with-lags 0–8). **Optional**
  pre-registered interaction: `elevation × LST` (thermal-envelope modifier) — fit as a labelled
  secondary M6b, not the primary M6.
- **9.3 Preprocessing:** `log1p` right-skewed layers (population, nightlights, distances);
  **standardize continuous predictors using TRAIN mean/SD only**, apply to val/test. Never fit
  scaling on val/test. No future information in any feature.
- **9.4 Split & tuning:** use the committed train/val/test split unchanged. Tune **C** on the
  **validation split by log loss** (Brier secondary). **Never tune to any test metric.**
- **9.5 Interim gate:** first fit M6 on **Batch A+B features only**. If it does not beat **M0
  (season)** on validation log loss, log it and proceed to add C+D, but treat a persistent
  sub-M0 result as the (honest) finding — do not chase accuracy by adding post-hoc features.
- **9.6 Convergence:** if any model fails to converge, STOP and report (do not silently raise
  `max_iter` without noting it).

## 10. Evaluation (identical framework — reuse the ladder's eval code)

Compute on the **test split**, on the **identical common-complete rows** as M1/M2/M5, with the
**same functions** used elsewhere in the repo (import them; do not re-implement calibration/DCA):

- **Discrimination:** AUC, PR-AUC. **Overall:** Brier.
- **Calibration:** calibration-in-the-large (intercept), calibration slope, reliability/ECE.
- **Recalibration:** train-fit Platt (selection train/val only).
- **Decision-analytic:** net benefit @ **p\*=0.30**; decision curve over p=0.05–0.50; continuous NB.
- **Primary contrasts (the point of M6):**
  - **ΔAUC and ΔNB of M6 vs M0** (does landscape beat season?)
  - **ΔAUC and ΔNB of M6 vs M2** (does static/landscape match dynamic climate-only?)
  - **ΔAUC and ΔNB of M6 vs M1** (the hard-to-beat recent-cases baseline — expected: M6 loses)
  - *(Secondary)* **M5 + geomatics vs M5** — does landscape add anything beyond the full hybrid?
- **Uncertainty:** cluster bootstrap on the **unit** (RDHS `geometry_id` / Colombia `GID_2`),
  **seed 20260612, B=1000** (match the ladder exactly); report the proportion of bootstrap
  replicates with Δ>0 and 95% CIs.

**Interpretation rules (pre-specified — write these into the report before looking at test):**
- If **M6 does not beat M0/M1 on net benefit** → the honest, expected result: *a purely spatial
  landscape model carries little standalone decision value* — strengthens the paper's caution.
- If **M6 improves AUC but not net benefit** → discrimination ≠ decision value (the paper's core
  point), report as such.
- If **M6 (or M5+geo) beats M1 on ΔNB with CI excluding 0** → **do NOT change any headline
  automatically.** Flag as a major finding requiring team review and PI sign-off; re-examine for
  leakage (esp. via healthcare-access #15, a detection confounder) before believing it.
